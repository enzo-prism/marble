# Marble 2.6 build 83 parser evaluation

Evaluated October 4, 2026. This is **Mac host evidence, not iPhone verification**.
The candidate is the reliability work based on `21bf511`; build 83 is the intended
release build, not an assertion that a binary has been uploaded or released.

## Method

A standalone Swift harness compiled the real `FoundationModelsWorkoutScanParser`,
`WorkoutDraftArbiter`, deterministic parser, exercise matcher and the two checked-in
evaluation corpora against the Mac's local Foundation Models runtime. The model
reported available. There was one model response sequence per case, with the app's
existing retry behavior; 114 cases completed with no reported `lastModelIssue`.
The process resumed from checkpoints once to prioritize three numeric failures.
No model prompts or generation schemas were changed for this evaluation.

Supporting unit enums, CSV numeric helpers and date merge code came from the app.
The host harness substituted a minimal metrics-profile value type for presentation
metadata; that type does not participate in the evaluated parse or scoring decisions.

The raw parser invokes the model on every input. The actual app first applies
`ModelEscalationPolicy`, retaining deterministic results for clean notation. Routed
results below combine the real policy/deterministic results with the **same cached
model outputs** before and after the policy change. This isolates the routing change
from model variability. Routed latency is an estimate from those component timings,
not an end-to-end phone or UI measurement. The historical September result is not
used as the before measurement.

## Results

| Measurement | Before policy fix | After policy fix |
|---|---:|---:|
| Routed total | 85/114 (74.6%) | 88/114 (77.2%) |
| Clean notation | 34/34 | 34/34 |
| Standard corpus | 42/43 | 42/43 |
| Standard prose | 8/9 | 8/9 |
| Hard corpus | 43/71 (60.6%) | 46/71 (64.8%) |
| Inputs routed to the model | 51/114 | 54/114 |
| Clean notation routed to the model | 0 | 0 |
| Estimated mean latency | 2.09 s | 2.25 s |
| Estimated median latency | ~1 ms | ~1 ms |
| Estimated p95 latency | 6.25 s | 6.76 s |

Calling the raw parser on all 114 cases passed 87/114 (76.3%), with mean 4.60 s,
median 4.10 s and p95 7.54 s. Its notation result was 33/34: a model selection
collapsed a rep ladder which the app's deterministic routing correctly preserved.
These results support keeping the fast deterministic path.

The deterministic parser alone remained 57/114, including 34/34 notation, before
and after the duration/rest hardening. An aggregate corpus pass rate does not mean
all values in every accepted workout are correct.

## Policy change and verified improvements

The policy now asks the model to read a movement when a single named source line
contains one explicit numeric `N sets` or `N rounds` count that disagrees with the
parsed count. It does not assign counts across multiple named lines or multiple
explicit counts. It also detects a missing load after `with [the] 32s`, including
for distance work. Rest wording such as `30s of rest`, `30s between sets`, and
punctuation before `rest` is excluded from that load cue.

The three additional escalations were repaired by the real Mac model in this run:

| Input | Previously retained parse | Verified model result |
|---|---|---|
| `jump rope 5 rounds of 3 min, 1 min rest` | One set | Five sets, each 180 s, with 60 s rest |
| `tricep extentions 3 sets 12 reps 40lbs` | One set with no reps | Three sets of 12 at 40 lb |
| `OHP 5x5 at 42.5` / `kettlebell swings 3x20 with the 24` / `farmer carry 3x40m with 32s`, default kg | Carry load omitted | Correct 42.5 kg / 24 kg / 32 kg loads, carry 3 × 40 m |

Additional reliability changes cover parenthesized/colon rest labels, decimal
minute shorthand, overflow-safe duration and CSV numeric conversion, and bounded
set expansion. They prevent crashes or silent allocation/truncation problems;
they are not claimed as a broad model-accuracy improvement.

## Residual numeric failures from the routed run

These are observed output mismatches, not hypothetical risks. Values not listed
below should not be inferred as having received exhaustive validation.

| Exact input | Observed mismatch | Reference |
|---|---|---|
| `20 minute plank circuit, 3 planks of 45 seconds each` | One 1,200-second set | Three 45-second sets; 20 minutes describes the circuit |
| `bench pyramid one thirty five for ten one fifty five for eight one seventy five for six` | Reps `[5, 3, 6]` | Reps `[10, 8, 6]` at weights `[135, 155, 175]` lb |
| `bench 3x8 185, incline db 3x10 60s` | Incline dumbbell load 20 | Incline dumbbell load 60 lb |
| `overhead press four sets of six at fifty then dips three sets of ten plus twenty`, default kg | Dips weighted sets labeled lb | Dips 3 × 10 at 20 kg; overhead press 4 × 6 at 50 kg |

The last case exposes a concrete unit-grounding gap: the model-unit mapper accepts
an explicit model answer of `lb`, although the source contains no weight unit.
The arbiter penalizes that guess but can still select it. The correct default is
already passed through the pipeline; a prompt retry is not a reliable remedy.
This report's 88/114 result includes that failure and must not be presented as
having corrected it.

Other failures include collapsed variable rep lists, omitted movements in long
prose, duplicate same-lift entries, and strict matcher differences such as
`ran`/`Run`, `rowed`/`Row`, and `Pushups`/`Push Ups`.

## Limits and device checklist

- The Mac model can differ from the iPhone model. No phone accuracy, latency,
  cancellation behavior or availability claim follows from this run.
- A single sample per case does not establish model stability across repeated
  runs, OS updates, locales or model asset versions.
- The existing scorer checks several scalar fields only on the first set and
  generally treats unspecified expected values as unchecked. It does not prove
  absence of invented fields. Name matching also contributes false negatives.
- Review remains necessary for model-derived numbers. Exercise the three repaired
  inputs and the residual examples above on iPhone, with kg and lb preferences.
- Separately test dictation, explicit lb overrides for kg users, Stop during
  interpretation, restored drafts, multi-session imports and stable Monthly
  Report insights. This parser evaluation does not replace those release gates.

## Paired unit-grounding verification

A second run evaluated all 114 inputs with the current routing policy, calling the
model only for its 54 routed cases. Both the old and updated arbiters received the
same candidate arrays, and full before/after drafts were retained. The unit-grounding
change improved 88/114 to 89/114 with no pass-to-fail regressions. The weighted-dips
case above changed from lb to the preferred kg while preserving weights and reps.
This is a separate sample from the routing evaluation, not an additive accuracy claim.
Twenty-two host boundary checks also passed, including explicit and mixed units,
spelled unit names, # notation and compact 80kgx8 / 225lbs×5 notation.

The correction uses the user's default only when the entire source has no explicit
weight-unit evidence. iOS compilation and exact-source release gates remain pending.
