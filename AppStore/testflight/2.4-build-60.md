## What to Test (en-US)

Marble 2.4 build 60 is a focused replacement candidate for two release issues.
From the default Add tab, confirm Start or open workout is always available and
can start a session even when no workout is active. Then import a workout where
the library contains duplicate exercise names: confirm the celebration uses the
exact exercise selected during review, and that choosing Create New never reports
a personal record from an unrelated same-named exercise. Recheck Add parsing,
structured review, save, Log, Progress, rest, and the active-workout accessory.
Send feedback with the smallest workout text and library setup that reproduces a
mismatch.

## Focused acceptance pass

- Fresh state: open Add with no active session, tap Start or open workout, verify
  the workout sheet appears, start a workout, log a set, and finish it.
- Existing session: the same action opens the active workout; the bottom accessory
  still opens it, and the rest timer keeps accessory priority.
- Deep links: `marble://workout`, `marble://train`, and `marble://split` reach the
  workout surface whether or not a session is active.
- Duplicate names, selected existing exercise: create two library exercises with
  the same display name but different histories, select one explicitly in import
  review, save, and verify PR celebration evaluates only that UUID's history.
- Duplicate names, Create New: choose Create New while a same-named exercise has
  history, save, and verify Marble does not claim that unrelated history as a PR.
- Regression: natural language, notation, Notes, Hevy/Strong CSV, unresolved-line
  retry, draft recovery, Shortcut handoff, active-session Add Set, Log modes,
  Progress, widgets, backup/restore, and shipped-2.3 migration.
- Accessibility: Start or open workout has a truthful VoiceOver label and reachable
  hit target at default and maximum Larger Text in light and dark appearance.

## Exit criteria
