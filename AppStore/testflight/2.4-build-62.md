# Marble 2.4 (62) TestFlight plan

Prepared for internal TestFlight from the exact GitHub `main` commit containing
the Progress redesign. Final source SHA, App Store Connect build ID, and GitHub
workflow evidence will be recorded after Apple processing completes.

## What to Test (en-US)

Marble 2.4 build 62 introduces a calm, minimal Progress overview. Confirm the
default Progress tab shows only a weekly status and Details action with generous
white space. Open Details and verify Summary, Training, Body & Habits, and
Milestones retain the weekly goal, highlights, filters, charts, reports, body
metrics, and records. Test light and dark appearance, maximum Larger Text,
VoiceOver, Reduce Motion, iPhone SE, regular iPhone, and iPad. Also smoke Add,
Log, imports, workout sessions, rest timer, and Settings.

## Focused acceptance pass

- Overview: the default Progress tab is quiet and uncluttered, with one readable
  weekly status, one clear Details action, and no duplicated metrics or controls.
- Details: weekly goal, daily highlights, consistency and volume, exercise
  filters, reports, body metrics, habits, supplements, and milestones remain
  organized and discoverable.
- Adaptivity: content remains usable in light and dark appearance, maximum
  Larger Text, VoiceOver, Reduce Motion, Increase Contrast, iPhone SE, regular
  iPhone, and iPad portrait and landscape.
- Regression: Add, Log, imports, workout sessions, rest timer, widgets, Settings,
  backup and restore, HealthKit boundaries, and shipped-data migration still work.

## Exit criteria

- Unit, focused Progress snapshot, smoke UI, accessibility, and screenshot flows
  pass with reviewed visual baselines.
- The signed build is uploaded from exact GitHub `main`, reaches `VALID`, and
  strict TestFlight validation reports no blocker.
- Internal `test group A` receives it through all-build access; do not add it
  manually or trigger external Beta App Review.
- The existing App Store 2.4 build 61 review submission remains untouched.
  TestFlight upload or internal distribution is not a public App Store release.

## App Store Connect commands

Create the en-US note once for the new build:

```sh
asc builds test-notes create \
  --build-id BUILD62_ID \
  --locale en-US \
  --whats-new "$(sed -n '/^## What to Test/,/^## Focused acceptance pass/p' AppStore/testflight/2.4-build-62.md | sed '1d;$d')"
```

For a retry or copy change, confirm the note exists and update it by build and
locale instead of calling `create` again:

```sh
asc builds test-notes list --build-id BUILD62_ID --output json
asc builds test-notes update \
  --build-id BUILD62_ID \
  --locale en-US \
  --whats-new "$(sed -n '/^## What to Test/,/^## Focused acceptance pass/p' AppStore/testflight/2.4-build-62.md | sed '1d;$d')"
```
