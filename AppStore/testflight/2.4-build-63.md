# Marble 2.4 (63) TestFlight plan

Prepared for internal TestFlight on 2026-08-30. Exact GitHub `main` source,
App Store Connect build ID, processing state, validation, and workflow evidence
must be filled in only after the signed upload is verified. The existing App
Store 2.4 build 61 submission must remain `WAITING_FOR_REVIEW` and untouched.

## What to Test (en-US)

Marble 2.4 build 63 makes Add more responsive and keeps the minimal Progress
overview lightweight. In Add, confirm `Bench Press 3x8 @ 185 lb` followed by
`Felt strong today` stays one workout with three sets, while titled weekday
headers such as `Monday — Push` and `Wednesday — Pull` still create two
workouts. Type and paste long notes or CSV exports and confirm preview feedback
appears after a short pause without stale rows. In Progress, confirm the default
page remains a quiet weekly status with one Details action, then open Details
and verify the full analytics remain available. Test light and dark appearance,
maximum Larger Text, VoiceOver, Reduce Motion, iPhone SE, regular iPhone, and iPad.

## Focused acceptance pass

- Add fidelity: trailing or leading relative-date prose remains a workout note;
  explicit titled weekday headers still split real multi-workout pastes, and an
  unreadable workout remains visible and blocks saving until it is reviewed.
- Add responsiveness: rapid typing does not publish stale preview results, row
  identity stays stable, and Apple Intelligence prewarming begins only after
  focused typing signals near-term use.
- Progress: Overview keeps the shipped build-62 whitespace and hierarchy while
  hidden charts, reports, records, body metrics, and supplement analytics are
  derived only after Details opens.
- Adaptivity: Add and Progress remain usable in light/dark appearance, maximum
  Larger Text, VoiceOver, Reduce Motion, iPhone SE, regular iPhone, and iPad.

## Exit criteria

- Unit, full snapshot, UI, accessibility, and shipped-source migration gates
  pass for the clean build-63 commit.
- Exact-merge GitHub CI passes before the TestFlight workflow is dispatched.
- The signed build reaches `VALID`; strict TestFlight validation reports no
  blocker; the en-US note is attached; internal `test group A` receives it
  through existing all-build access.
- App Review remains on 2.4 build 61. Do not cancel, replace, resubmit, trigger
  external Beta App Review, or issue a public App Store release.

## App Store Connect commands

Create the en-US note once for the verified build:

```sh
asc builds test-notes create \
  --build-id BUILD63_ID \
  --locale en-US \
  --whats-new "$(sed -n '/^## What to Test/,/^## Focused acceptance pass/p' AppStore/testflight/2.4-build-63.md | sed '1d;$d')"
```

For a retry or copy change, update the existing localization instead of creating
a duplicate:

```sh
asc builds test-notes list --build-id BUILD63_ID --output json
asc builds test-notes update \
  --build-id BUILD63_ID \
  --locale en-US \
  --whats-new "$(sed -n '/^## What to Test/,/^## Focused acceptance pass/p' AppStore/testflight/2.4-build-63.md | sed '1d;$d')"
```
